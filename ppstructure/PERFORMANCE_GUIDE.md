# PaddleOCR 性能优化指南

## 📊 性能分析

### 当前问题
你遇到的情况：**单张图片处理时间 10+ 秒**

#### 时间分解
```
总耗时: ~10秒
├─ 模型初始化: 6-7秒  ⚠️ 主要瓶颈
│  ├─ 检测模型 (det): ~1.5s
│  ├─ 识别模型 (rec): ~1.5s
│  ├─ 布局模型 (layout): ~2s
│  ├─ 表格模型 (table): ~1.5s
│  └─ 方向模型 (orientation): ~0.5s
│
├─ 实际推理: ~1秒 ✅
│  ├─ 文本检测: 0.127s
│  └─ 文本识别: 0.490s
│
└─ 后处理+保存: ~2秒
   ├─ Layout分析: ~1.5s
   └─ 结果保存: ~0.5s
```

### 根本原因
1. **冷启动开销**：每次运行都要重新加载 5 个深度学习模型到 GPU
2. **不必要的模型**：大多数场景只需要检测+识别，但默认加载了布局、表格等所有模型
3. **后处理耗时**：Layout 分析和可视化绘制占用大量时间

## 🚀 优化方案

### 方案 1: 快速模式（推荐）⚡
**只做 OCR，跳过布局和表格分析**

```powershell
.\quick_ocr_only.ps1 "your_image.jpg"
```

**预期速度**: 2-3 秒（模型初始化 1.5s + 推理 1s）
**速度提升**: **5倍**

适用场景：
- 纯文本识别
- 不需要表格识别
- 不需要版面分析

### 方案 2: 批量处理模式 📦
**一次处理多张图片，模型只初始化一次**

```powershell
.\batch_ocr.ps1 "image_folder_path"
```

**预期速度**: 
- 第一张图: 7秒（包含初始化）
- 后续每张: **1秒/张** ⚡⚡⚡

**速度提升**: 批量处理 **10倍+**

适用场景：
- 批量处理多张图片
- 需要完整功能（布局+表格+OCR）

### 方案 3: 优化模式 ⚙️
**平衡速度和功能**

```powershell
.\optimized_ocr.ps1 "your_image.jpg"
```

**预期速度**: 4-5 秒
**优化点**:
- 增加批处理大小 (`rec_batch_num=8`)
- 降低检测阈值 (`det_db_box_thresh=0.5`)
- 限制图片尺寸 (`det_limit_side_len=960`)
- GPU 内存优化

## 📈 参数调优

### 关键参数说明

| 参数 | 默认值 | 优化值 | 说明 |
|------|--------|--------|------|
| `--layout` | True | **False** | 禁用布局分析，节省 2s |
| `--table` | True | **False** | 禁用表格识别，节省 1.5s |
| `--rec_batch_num` | 6 | **8-16** | 增加批处理，提速 20-30% |
| `--det_limit_side_len` | 960 | **640-960** | 降低可加速，但影响精度 |
| `--det_db_box_thresh` | 0.6 | **0.5** | 降低可检测更多文本 |
| `--rec_image_shape` | 3,48,320 | **3,32,320** | 减小高度可加速 |

### GPU 环境变量优化

```powershell
$env:FLAGS_fraction_of_gpu_memory_to_use = "0.8"  # 使用更多GPU内存
$env:FLAGS_cudnn_exhaustive_search = "True"       # 自动寻找最快算法
$env:FLAGS_cudnn_deterministic = "False"          # 允许非确定性以换取速度
```

## 🔧 故障排查

### Q: 为什么还是很慢？
A: 检查以下项：
1. GPU 是否真正启用？查看日志中是否有 "GPU ID: 0"
2. 是否有 CUDNN 版本警告？考虑重装匹配版本的 Paddle
3. 是否启用了不必要的功能（layout/table）？

### Q: 批量处理如何更快？
A: 
1. 增加 `rec_batch_num` 到 16 或更高
2. 使用多进程处理不同图片
3. 考虑使用 TensorRT

### Q: 精度会下降吗？
A: 
- 快速模式：只是跳过布局分析，OCR 精度不变
- 调参优化：可能略微影响，但通常可忽略
- 建议先用默认参数测试，再逐步调优

## 💡 最佳实践

1. **开发调试**: 使用快速模式，快速迭代
2. **生产环境**: 使用批量模式，提高吞吐量
3. **高精度需求**: 使用原始模式，保证质量
4. **实时应用**: 考虑部署推理服务，保持模型常驻内存
